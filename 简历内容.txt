【项目简介】

基于 MCP 协议的 14 工具 AI Agent 旅行规划应用。自研 LangGraph ReAct Agent 协同 5 个 MCP Tool Server 完成路线规划、POI 搜索、联网检索、知识库 RAG、流式交互、技能自进化等全链路。解决 LLM 输出不可靠、上下文膨胀、环境兼容性等 Agent 工程化核心问题。自建 12 用例评估框架，工具准确率 ~92%，首 Token 延迟 ~1s。

【创新亮点】

1. code_run 沙箱执行——单一工具替代 N 个专用工具

问题：批量计算/数据排序/多条件筛选时，需多次工具调用 + LLM 手动拼接，耗时 10s+ 且易出错。
方案：借鉴 GenericAgent 理念，子进程沙箱执行 Python（30s 超时 + 模块白名单 + 危险函数拦截）。Agent 自主编写代码处理数据。
效果：3 条以上数据排序从 ~10s 降至 ~1s，工具集从封闭式转向开放式。


2. 导航链接可靠性——准确率 ~40% → 100%

问题：LLM 自行编造百度地图 URL，坐标错误率约 60%。
方案：坐标存入后端缓存，SSE search_ready 事件异步推送 ID，前端注入按钮。确定性计算与语言生成解耦。
效果：导航准确率 100%。该策略推广至知识库、技能库——降低 Agent 不可靠性的核心方法。


3. 上下文智能压缩——Token 消耗 -35%

问题：旅游规划 15+ 工具调用，36-44 条消息全堆在上下文，每轮推理重传。
方案：(1) TF-IDF 句子评分截断——保留高分句，丢弃"向前步行10米"类低价值细节；(2) Plan Mode——探索与规划分离，搜索输出写入文件，主 Agent 只读结论。
效果：Token -35%，规划质量未退化。不用 LLM 摘要（会额外消耗 Token）。


4. 环境兼容性治理——14 个 MCP 工具冷启动 100%

问题：Conda 环境下 onnxruntime DLL 失败、ChromaDB 段错误、sentence-transformers 版本冲突。
方案：依赖分级——稳定依赖顶层导入，不稳定依赖惰性加载或降级。最终以 jieba + sklearn TF-IDF 回退，零二进制依赖。
效果：14 个 MCP 工具冷启动成功率 100%，知识库检索可用级质量。


5. 混合定位降级——桌面端可用率 0% → 100%

问题：台式机无 GPS，浏览器 Geolocation API 直接报错。
方案：浏览器 API（8s 超时）→ 自动切换手动输入 → 高德 POI 搜索 + 地理编码双解析。
效果：桌面端定位可用率 100%。


6. SSE 三级事件流——感知延迟 -80%

问题：Agent 同步阻塞，5-10s 无反馈；工具调用黑盒。
方案：text（token 级流式）+ tool_start/tool_end（含耗时）+ search_ready（坐标预取），三级独立推送。
效果：首 Token < 1s，感知等待从 5-10s 降至 < 1s。


7. 技能自进化 + 多维评价

问题：每次规划从零开始无复用；去过的地方重复推荐。
方案：SOP 结构化技能库（策略 + 已验证路线）+ 6 维度评价（性价比/拥挤/出片/趣味/匹配/推荐）。评分 ≥4 可再推，<2 排除。
效果：同城市不同偏好可复用策略，规划时间缩短 ~60%。


【评估体系】

自建 12 用例自动评估框架，覆盖天气/路线/POI/知识库/旅游规划场景。支持 --save-baseline 对比优化前后。

通过率 83.3% | 工具准确率 ~92% | 关键词匹配率 91.7% | 首 Token ~1s | 错误率 < 10%
