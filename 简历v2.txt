MCP 智能旅行助手（吃喝玩乐小助手）

Python · FastAPI · LangGraph · MCP · DeepSeek · SSE · SQLite · JavaScript
2025.05 — 至今 | github.com/Ali001716/travel-agent


【项目简介】

基于 MCP 协议构建多工具协同的旅行规划 Agent，使用 LangGraph 实现 ReAct 智能体架构，对接 5 类 MCP 工具服务，完成 POI 检索、路线规划、联网搜索、知识库 RAG、流式对话、用户偏好自适应等能力。针对 LLM 幻觉、上下文膨胀、环境依赖冲突、工具调用冗余等工程问题，设计分层工具架构、上下文压缩策略、确定性逻辑剥离等优化方案，自建多维度用户偏好模型，实现个性化旅行推荐；构建 12 用例评估框架，完成 Agent 稳定性迭代。


【核心亮点】

1. 幻觉治理——分离 LLM 生成与确定性计算

问题：LLM 推荐地点时自行编造百度地图链接，坐标错误率约 60%。
思路：将链接生成权从 LLM 剥离。搜索结果坐标存入后端缓存，LLM 只负责推荐理由等自然语言部分，前端通过 SSE 事件异步获取坐标并注入导航按钮。
效果：导航准确率从 ~40% 提升到可用状态，该设计思路推广至知识库、技能库——识别 LLM 能力边界、将确定性计算剥离给传统代码，是降低 Agent 不可靠性的核心方法。


2. 上下文优化——Plan Mode + TF-IDF 句子级压缩

问题：旅游规划单次调用 15+ 工具，36-44 条消息全堆在上下文，后续每轮 LLM 推理重传全部历史，Token 消耗线性增长。
思路：(1) Plan Mode 将搜索与规划阶段分离，搜索输出写入文件，主 Agent 上下文只保留结论摘要；(2) 对旧工具消息用 jieba 分词 + TfidfVectorizer 做句子级评分，保留高信息密度句子（数字、地名），丢弃低价值细节（"向前步行 10 米"）。
效果：Token 消耗降低约三分之一，规划质量未退化。注意——这里选用 TF-IDF 而非再调一次 LLM 做摘要，因为用 LLM 压缩 LLM 的上下文等于把省下的 Token 又花出去了。


3. 分层工具体系——专用工具 + 代码沙箱兜底

问题：Agent 面对批量排序、多条件筛选等长尾需求时，专用工具覆盖不到，只能多次调用 + LLM 手动拼接，慢且易错。
思路：借鉴 GenericAgent 的"单一可编程工具"理念，引入 Python 沙箱执行。子进程隔离、30s 超时、模块白名单、危险函数拦截。专用工具覆盖高频场景（天气、路线），code_run 覆盖长尾场景（批量计算、数据转换）。Prompt 中定义三条使用规则——(1) 现有工具无法一步到位；(2) 涉及 3 条以上数据；(3) 非实时查询——三层同时满足才触发，避免工具滥用。
效果：3 条以上数据排序从多次工具调用 + LLM 拼接（~10s）降至单次代码执行（~1s）。


4. 轻量化 RAG——规避 embedding 环境依赖

问题：Windows Conda 环境下，onnxruntime DLL 加载失败、ChromaDB 段错误、sentence-transformers 版本冲突，三个问题连环踩坑。
思路：放弃"修环境"的思路，改为换方案。jieba 分词 + sklearn TfidfVectorizer + 余弦相似度，三个依赖都是纯 Python，零二进制，环境即装即用。知识库和技能库共用同一套检索架构。
效果：14 个 MCP 工具冷启动成功率 100%。取舍很明确——精度不如专用 embedding 模型，但可用性和可移植性完胜。一个永远能跑的 70 分方案，胜过需要特定环境才能跑的 90 分方案。


5. 个性化推荐建模——6 维评分 + 分级处理

问题：通常"去过的地方就不推"是一刀切——但评分 4.5 的店用户可能想二刷，评分 1 的才该永久排除。
思路：自建 6 维评分体系——性价比、拥挤度、出片指数、趣味性、符合预期、推荐度。根据综合评分分三档处理：高分优先推荐，中等作为备选，低分严格排除。未评分的默认保守处理（不主动推）。评分数据与技能库联动——同城市同风格的已验证行程可直接复用策略。
效果：用户偏好从"去过/没去过"升级为"多喜欢/多不喜欢"，推荐粒度从二值变为连续。


6. 流式交互与工程化——SSE 三级事件 + 容器化

问题：Agent 同步阻塞调用时用户等待 5-10s 无反馈；工具调用黑盒，无法判断卡死还是执行中。
思路：基于 astream_events 实现三级 SSE 事件流——text（token 级流式字符）、tool_start/tool_end（含耗时毫秒数）、search_ready（坐标缓存 ID 预推）。前端按事件类型独立响应，工具状态实时可见。
工程化：Dockerfile + docker-compose.yml 一键构建启动；Render 云平台部署配置；start.bat + QR 码本地零门槛启动。


【评估体系】

自建 12 用例自动化评估框架，覆盖天气/路线/POI/知识库/旅游规划场景。自动采集工具调用准确率、首 Token 延迟、关键词匹配率、错误率等指标。支持 --save-baseline 快照对比，每次代码改动后可量化验证是否引入回归。
